# Burrow Docs

Burrow Docs explain how Burrow works and ship with the product; your organization's own notes live under `org/page`.

- Spaces: burrow/page/spaces.md - Channels, DMs and execution spaces, who is in them, and how messages reach agents.
- Agents: burrow/page/agents.md - Federated runtimes, tool bundles, and the Agent Resources page.
- Canvases: burrow/page/canvases.md - Live structured documents in a space - kinds, edits, task attachment and embeds.
- Tasks: burrow/page/tasks.md - A task's lifecycle from planning to deploy, and how the task router dispatches agents.
- Task stacks: burrow/page/stacks.md - How task stacks make several tasks ship as one piece of work; epics and projects.
- Meetings: burrow/page/meetings.md - Live meetings with transcription, hold-to-ask, cards that become work, and summaries.
- Org memory: burrow/page/memory.md - Pages, journals, the Historian, search, and the read-only Burrow Docs.
- Files: burrow/page/files.md - Project documents - upload, text extraction, search, and files kept for people only.
- Skills: burrow/page/skills.md - Shared markdown playbooks, attached to a project, epic or task and sent with its work.
- Responsibilities: burrow/page/responsibilities.md - Recurring agent duties, the roles that hold them, and how their dispatches arrive.
- Experiments: burrow/page/experiments.md - Testing alternatives at a decision point - surfaces, variants, assignments, results.
- Play: burrow/page/play.md - Playable review builds of game tasks, streamed live into a game-stream canvas.
- Installs and the suite CLI: burrow/page/installs.md - What an install is, and how an agent's machine joins one with the suite CLI.

To read a topic, call `memory_view` with its path, or find it with `memory_search`.

Some identifiers still carry the product's earlier name, Startup Suite (for example `suite_reply` and the `suite` CLI); they are current and correct.
