## 4. Defensive clauses removed: the trade-off, stated

Some of the deleted clauses were written on purpose as runtime insurance
against a FUTURE contract change, and their comments said so. The 1.20 checker
proves them unreachable today, and CI compiles with `--warnings-as-errors`, so
they cannot stay. Measured on 1.20.2: **the checker does NOT warn when a local
call later receives a value that no clause matches** (a probe with an
`if`-produced union passed to a single-clause `defp` compiled silently). So
removing one of these clauses turns a handled refusal into a runtime raise
if the contract changes later. Each site is listed so a reviewer can disagree:

| Site | Was | Now |
|---|---|---|
| `ToolSurface.supplied_stage_id_envelope/3` catch-all | refusal envelope for an unknown reason | 3 exact heads. A 4th reason from `resolve_ack_stage_id/2` raises FunctionClauseError. The comment says so. |
| `ArchitectureReviewPlan.fetch_sibling_tasks_slot/1`, `fetch_adr_index_slot/0`, `ArchitectureCronSweep.adr_index/0` | `other ->` logs and renders the empty/unavailable block | total `{:ok, %{...}} =` match; a new return shape raises MatchError. The comment says so. |
| `ContextGatherer.put_slot/3` `other ->` | records `{:unexpected_shape, other}` | **kept the guarantee**: `safe_gather/2` now does the contract `case` inside its existing `rescue`, so an off-contract value is still recorded as `{:unexpected_shape, value}` and `gather/2` still never raises. |
| `Chat.emit_inbox_for_mentions/1` `inbox_emit_allowed?/2` seam | always-`true` predicate, kept for a future external-scope gate | seam removed; the comment names where an `ExternalScope` filter belongs. Behaviour unchanged. |
| `BoardComponent.has_active_run?/1` | `false` stub behind two "Active run" spans | stub and both spans removed. They never rendered. |

## 5. Real defects the checker found (behaviour changes)

1. **`MCPController.jsonable/1`**: `if Jason.Encoder.impl_for(value)` is always
   true. `Jason.Encoder` sets `@fallback_to_any true`, so a struct with no
   encoder resolves to `Jason.Encoder.Any`, whose `encode/2` raises. The
   `inspect/1` branch, which existed to stop exactly that 500, was dead. Now
   `Jason.Encoder.Any -> inspect(value)`.
2. **`GitShellRunner.create_branch/3`**: `true <- base_sha != "" or {:error, ...}`
   yields `true` or the tuple, never `false`. So the `else false ->` clause was
   dead, and an empty `rev-parse` fell through every `else` clause and raised
   WithClauseError. Now `{:error, {:base_branch_not_found, _}} = err -> err`.
3. **`ContextDelta.normalize_value/1`**: the `%Date{}` head sat after
   `is_map/1`, so a Date went to `normalize_map/1` and raised
   Protocol.UndefinedError (`Map.new/2` on a struct; reproduced on 1.20.2).
   The heads are reordered. Regression test:
   `test/platform/agents/context_delta_test.exs`.
4. **`PresenceHooks.sender_avatar_seed/2`** (dead code only, behaviour kept):
   `author_snapshot_name(msg) || pid || "user"`. `author_snapshot_name/1`
   falls back to `"User"`, never nil, so a snapshotless message is seeded
   `"User"` and never by its participant id. The dead `|| pid || "user"` was
   deleted and the behaviour kept. Whether the pid fallback was the intent is
   a product question for whoever owns avatars.

No regression test was added for (1) or (2). (1) is reachable only through a
tool refusal that carries a non-encodable struct. I did not search the tool
surface for one, and no existing test builds one. (2) needs `git rev-parse` to
succeed with empty output.

## 7. Not a type warning: ExUnit 1.20 changed its summary line

Measured on 1.20.2. The run summary is now `Result: N passed`. With failures
it is `Result: P/N passed` followed by `Failed: K tests`, and with nothing run
it is `Result: 0 tests`. A `(... doctests, ... tests)` breakdown and
`, N skipped` / `, N excluded` may follow. The old `N tests, M failures` line
is gone. Both CI test-count floors grepped the old shape (`Run tests`
`assert_test_count_floor` and `Run module tests`). On 1.20 they would have
failed a green suite with "printed no ExUnit summary line". Both now grep
`Result: [0-9]+(/[0-9]+)? (passed|tests)` and take the last number as the
total. That total includes doctests, so it reads slightly higher than the old
`M tests`, which excluded them. `CiCrashGuardTest` pins the new grep. The
failure-block shape (`  1) test name (Module)` then `file.exs:N`), which the
retry harvest's awk reads, is unchanged.

Anything outside this repo that parses `N tests, M failures` out of a
`mix test` log (agent tooling, evidence templates) will read nothing on 1.20.

The moon test rig does not depend on the summary line. Checked in stage 2:
neither `~/cron/moon-mix-test.sh` nor `core-test.sh` greps it. Both take
the verdict from `mix test`'s exit code, so a green 1.20.2 run reads as
green there.

## 8. Stage 2: runtime fallout from the full suite

Both full runs were on `3b5ca5c08`, on moon, with no `--include slow`
(that set is run separately):

| rig | image | result | failures |
|---|---|---|---|
| private 1.20.2 | `localhost/core-test:1.20.2-otp-28-slim-cc` | `Result: 20136/20138 passed`, 3 skipped, 13 excluded | 2 |
| stock 1.19.5 | `localhost/core-test:1.19.5-otp-28-slim-cc` | the same 2 failures | 2 |

The two failures are the same on both rigs, and neither is a flake or a
1.20 behaviour change. They are line-count ratchets that stage 1's own
deletions in `5aa722491` tripped: `ChatLiveCodeLineRatchetTest` (2348 vs
pinned 2350) and `TasksLiveShellNonAccretionTest` GUARD 4 (650 vs 652).
Both counts went down. The pins were moved, with the reason, in the commit
that follows `3b5ca5c08`.

**A runtime deprecation that compile gates cannot see.** On 1.20.2,
`File.stream!(path, modes, line_or_bytes)` is deprecated, and the warning is
raised when the call RUNS, not when it compiles. That is why stage 1's
`--warnings-as-errors` compiles were clean while the full suite printed it
201 times. Three call sites in `lib/` passed `[]` modes first:

- `Platform.Chat.AttachmentStorage.Adapter.LocalDisk.read_stream/1`
- `Platform.Chat.AttachmentStorage.Adapter.LocalDisk.hash_and_size/1`
- `PlatformWeb.FilesLive.hash_path/1`

All three now use `File.stream!(path, bytes)`. With no modes, the 2-arity
form is the same call. It exists on 1.19.5 too: on moon it gave
`["abcd", "ef"]` for a 6-byte file at 4 bytes per chunk under both images.

**Test-file warnings are not gated.** CI compiles `test/**/*_test.exs`
through `mix test`, not under `--warnings-as-errors` (see the "DOES NOT
COVER" note in ci.yml). The suite already printed 270 unique test-file
warning locations on 1.19.5. 1.20.2 prints 315: 46 new locations, and one
1.19.5 location (`retry_auto_approval_test.exs:270`) is gone. Most new ones
are the checker proving an assertion statically. Examples are
`refute is_nil(f(x))` where `f` returns a map, `refute result == {:ok, 0}`
just after `{:error, _} = result` was matched, and branches over a
compile-time table that are always true. Changing those tests just to hide
the checker's proof would be suppression with extra steps, so they are left
alone. There is one exception. `runner_test.exs:178-179` matched on `0.0`,
which both versions warn about, and now matches on `+0.0`. The runner
returns a literal positive zero.
