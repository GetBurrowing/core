## Locked design decisions

### 1. Module location & name

`Platform.Org.Wiki.Context` at `apps/platform/lib/platform/org/wiki/context.ex`.

This is the canonical name. NOT `Platform.Org.PreambleBuilder` — that was
an earlier P4 attempt against a different task; T4 owns the canonical
location and the older module name should not be revived.

### 2. Output shape — TWO public functions

The task description AC says the surface returns `%{path => content}`.
The plan body asks for a metadata-rich shape `{:ok, %{pages, used_tokens,
dropped, truncated}}`. Both ship:

```elixir
@spec build_preamble(opts :: keyword()) :: %{String.t() => String.t()}
def build_preamble(opts \\ [])

@spec build_preamble_with_metadata(opts :: keyword()) ::
        {:ok, %{
          pages: %{String.t() => String.t()},
          used_tokens: non_neg_integer(),
          dropped: [%{path: String.t(), reason: :budget_overrun | :scope}],
          truncated: [%{path: String.t(), lost_tokens: non_neg_integer()}]
        }}
def build_preamble_with_metadata(opts \\ [])
```

Call sites use `build_preamble/1` — they get the bare map, drop-in
compatible with the existing `:org` key in `ContextAssembler` and
`ContextPlane`. Telemetry / observability code can use the
`*_with_metadata` form.

### 3. Token budget — 4096, configurable, char/4 estimator

```elixir
defp estimate_tokens(content) when is_binary(content) do
  div(byte_size(content), 4)
end
```

Budget knob: `Application.get_env(:platform, :preamble_token_budget, 4096)`.
Per-call override via `:budget` opt for tests.

V1 estimator. Replace with a real tokenizer when the wiki holds enough
preamble content for the heuristic to bite — until then, the char/4
heuristic is what Anthropic and OpenAI both publish for English.

### 4. Selection rule

Pages from `Platform.Org.Wiki.list_pages/1` where:

- `frontmatter["preamble"] == true`, AND
- `file_key` starts with one of the accessible-namespace prefixes:
  - `"org/"` (always)
  - `"project/<task.project_id>/"` (when `:task` opt is set and task has project_id)
  - `"space/<space_id>/"` (when `:space_id` opt is set)

Pages outside scope go into `dropped` with `reason: :scope` and are
NOT visible in the returned map.

### 5. Ordering

Stable sort by `{band(file_key), file_key}`:

- band 0: `org/*`
- band 1: `project/*`
- band 2: `space/*`

Within a band, lex `asc` on `file_key`. Deterministic, no recency
weighting (preamble pages are curated).

### 6. Eviction algorithm (the heart of stage 2)

Pure, deterministic walk. For each page in sort order:

1. Compute `tokens = estimate_tokens(annotated_content)` where
   `annotated_content` already includes the BEGIN/END wrappers (so the
   budget accounts for them honestly).
2. If `used_tokens + tokens <= budget` → include wholesale.
3. Else if NO pages are yet included AND `tokens > budget` → TRUNCATE
   this single page (see §7 below). Include it. Record in `truncated`.
4. Else → DROP this page. Record in `dropped` with `:budget_overrun`.
5. Keep walking — later, smaller pages that still fit are still
   included after a dropped one. This matches the AC's "lex-order drop"
   semantic: lower-band, smaller pages always win over higher-band,
   larger pages.

### 7. Truncation — paragraph-boundary cut + literal `[truncated]` sentinel

**Alex's binding override (2026-05-19):** Use a literal `[truncated]`
sentinel (NOT the plan's `<!-- TRUNCATED: N tokens dropped -->` HTML
comment). The task description's AC reads "page included up to budget
cliff, with `[truncated]` sentinel"; AC wins over plan body.

Algorithm:

- Compute `target_byte_budget = (budget - tokens_for_annotation - tokens_for_marker) * 4`
- Find the LAST `\n\n` at byte offset ≤ `target_byte_budget` in the body.
- Cut the body at that offset.
- Append `\n\n[truncated]` to the truncated body.
- Wrap the whole thing in BEGIN/END annotation markers (§8).
- Record `%{path: ..., lost_tokens: estimate_tokens(dropped_tail)}` in
  the `truncated` list.

If there's no `\n\n` in the body at all (single-paragraph mega-doc),
fall back to a hard byte cut at `target_byte_budget` and append the
sentinel.

### 8. Section annotation — BEGIN/END comment markers

Each included page's value in the returned map:

```
<!-- BEGIN org-preamble page="<file_key>" version="<v>" -->
<body-or-truncated-body>
<!-- END org-preamble page="<file_key>" -->
```

HTML-comment delimiters survive markdown rendering. They give an agent
an unambiguous boundary between injected preamble and user input.

The map KEY is the raw `file_key` (no annotation in the key) so any UI
code that introspects `Map.keys(context.org)` keeps working.
